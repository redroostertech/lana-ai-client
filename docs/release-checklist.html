Phase 1. Settle the code

Nothing gets built until the code it comes from is final.

  1. 1Server code final for this releaseLANA-AI production. The engine is built from it.
  2. 2Write down what this release is built fromFill in the fields at the top. A changed pin later means that piece is built again for every system. Before settling the redactor pin, check it has everything the cloud redactor image needs (it must listen on IPv4 and IPv6, REDACTOR_BIND_HOST=all); otherwise step 11 forces a new redactor pin and all four redactor pieces rebuilt.

Phase 4. Release the server

Firms' servers go before the app reaches them: an app whose engine is newer than the firm's server stops working for that firm.

  1. 9Classifiers checkedrelease.sh step 0 (PINS) decides. Publish any missing archive to models.lanaai.io first.
  2. 10Signed server update for boxes (on-prem)scripts/release/release.sh: signed, staged, verified, published to releases.lanaai.io/server/updates/.
  3. 11Cloud images built and pushedFirst, the prerequisites: (1) the pinned lana-redactor commit listens on IPv4 and IPv6 (build-images.sh refuses otherwise); (2) release.sh records the Railway chef image, not the old lana-stack; (3) the registry and Railway access are set on Heroku. Then: the four Railway images (lana-chef, lana-embed, lana-redactor, lana-minio) built with deploy/railway/build-images.sh on an Azure Linux VM, pushed with push-images.sh to LANA's registry (stored on R2, never GitHub), the control plane RAILWAY_IMAGE_* settings and the update policy set to the new digests (QA, then prod), and the cloud test server brought up to the release.
  4. 12Release recorded in the portal
  5. 13Each firm's server updated, Norton firstTo the engine commit or newer, before that firm's team gets the new app.

Rules that always apply

  • Work lands on development in every repo; a release moves development to production with Michael's yes.
  • Everything is hosted on Cloudflare R2. Azure is only for build VMs, deleted when each build ends.
  • A new backend commit needs new engine builds only when the app should carry it; then all four systems are rebuilt.
  • Never print secrets, signed links or passwords. Never put a GitHub token on a build VM.
